# デュエマ カード一覧ビューア 設計書

作成日：2026-11-17
状態：ユーザー承認待ち

## 1. 目的と背景

公式のカード検索（dm.takaratomy.co.jp/card/）は絞り込みが充実していますが、1ページに表示できる件数が少なく、何度もスクロールやページ送りが必要です。また、公式ではカードの価格、メルカリでの最安値、買取価格、関連動画がわかりません。

このツールで、次の2つができるようにします。

1. 絞り込んだ結果を、1画面にたくさん並べてひと目で見られる。
2. カードを選ぶと、買う・売る・調べるための情報にすぐ移れる（メルカリ、カーナベル、YouTube の動画）。

ユーザー自身が不便を感じて考えたツールで、似たサイト（foliva：1ページ20件、公式：1ページ50件程度）よりも一覧性で差別化します。

## 2. 方針（ユーザーが決めたこと）

- 一般に公開する **非営利のファンサイト**。**広告は付けない**（アフィリエイトや寄付も含め、収益化はしない）。
- **カード画像は表示する**。タカラトミーの許諾は取っていない。リスクについてはユーザーに説明済み。
- **画像はコピーを保存しない**。公式サイトの画像 URL をそのまま表示する。
- カードデータは、公式のカード検索から **自動で読み取って** 作る（案A）。
- 画面の形は第5章のとおり（ユーザー確認済み）。
- 問い合わせ先は、このサイト **専用の Gmail アドレス** をユーザーが作って使う。
- GitHub・Cloudflare のアカウントは **ユーザー自身が作り**、公開作業もユーザーが行う（作る人は手順書を用意し、一緒に案内する）。
- YouTube 動画は、サイト内に表示しない。**カード名で YouTube を検索した結果のページを開くボタン** にする（ユーザーが決定。動画のサムネイル表示と YouTube API は使わない）。

## 3. 目標・やらないこと・失敗とみなすこと

**目標**
- PC では1画面に40〜60枚、スマホでは20枚以上のカードが見えること。
- 公式とほぼ同じ絞り込みができ、条件を変えるとすぐ（体感で0.3秒以内）一覧が変わること。
- カードを選ぶと、メルカリ（販売中・安い順）、カーナベル、公式の詳細ページ、YouTube の検索結果にすぐ移れること。

**やらないこと**
- 広告、アフィリエイト、会員登録、ログイン。
- メルカリやカーナベルの **価格の数字を画面に出すこと**（自動読み取りは規約違反のおそれがあるため。リンクで開く形にする）。
- デッキ作成、価格推移グラフ、相場の計算。
- カード画像を自分のサーバーに保存すること。
- 殿堂入り（使用制限）の表示（最初の版では入れない。作る人の判断）。
- サイト内に YouTube の動画やサムネイルを表示すること。YouTube API を使うこと。

**失敗とみなすこと（動いても失敗）**
- 公式サイトに大きな負担をかけること（短時間に大量に読み取る、すべての画像を一度に読み込むなど）。
- 公式のサイトや商品だと誤解されるような見た目や名前にすること。
- 画像が出なくなったときに、一覧が使えなくなること。

## 4. 制約・前提

- **公式サイトの読み取り**：robots.txt で禁止されているのは `/wp-admin/` だけで、`/card/` と `/wp-content/card/cardimage/` は禁止されていない（2026-11-17 確認）。待ち時間の指定（Crawl-delay）はないが、**1秒に1回以下**の速さで読み取る。読み取りプログラムの User-Agent には、サイトの URL と専用 Gmail アドレスを入れる。
- **カード数**：公式の表示で 24,056枚（2026-11-17 時点）。
- **詳細ページの URL**：`https://dm.takaratomy.co.jp/card/detail/?id={セットID}-{カード番号}`（例 `dm26ex5-SEC001CHO`）
- **画像の URL**：`https://dm.takaratomy.co.jp/wp-content/card/cardimage/{同じID}.jpg`
- **詳細ページに載っている項目**：カード名、カードの種類、文明、レアリティ、パワー、コスト、マナ、種族、イラストレーター、特殊能力（能力の文章）、フレーバー、収録商品。ツインパクトなど、1枚に2つの面があるカードもある。
- **公式の絞り込み項目**：フリーワード（カード名・読み・テキスト・種族・フレーバー・イラストレーター）、文明（単色か多色か、多色の条件）、コスト範囲、カードの種類、ツインパクトかどうか、種族、レアリティ、特殊能力、パワー範囲、商品名、フォーマット、イラストレーター。並び順は発売日・カード名・コスト・パワー。「同名カードを表示する」の切り替えあり。
- **費用**：GitHub（Actions）と Cloudflare Pages の無料の枠で収める。

## 5. 画面（ユーザー確認済み）

```
┌──────────────────────────────────────────────┬──────────────────────┐
│ [カード名・能力で検索____] 文明[火水自光闇ゼ] コスト[1-15]  │ 《カード名》            │
│ 種類[▾] 種族[▾] パック[▾] …詳細条件  並び:コスト順▾  1,284枚 │ (公式のカード画像・大)  │
├──────────────────────────────────────────────┤ 火 / コスト6 / パワー6000 │
│ [画][画][画][画][画][画][画][画][画][画]             │ 種族・能力の文章       │
│ [画][画][画][画][画][画][画][画][画][画]             │ [公式の詳細ページ]      │
│ [画][画][画][画][画][画][画][画][画][画]             │ [メルカリ 販売中・安い順]│
│ ...（スクロールすると続きが出る）                   │ [カーナベル 販売/買取]  │
│                                              │ [YouTube で動画を探す]  │
└──────────────────────────────────────────────┴──────────────────────┘
```

- 一覧の1枚には、画像を小さく表示し、その下か上にコストとカード名を1行で出す。画像が読み込めないときは、**文字のカード**（左端に文明の色の帯、丸の中にコスト、カード名、パワー、種族）を表示する。
- 一覧の大きさ（1列に何枚並べるか）は、ユーザーが3段階くらいで切り替えられるようにする（作る人の判断）。
- PC は右側に詳細を出す。スマホは下から詳細の画面を出す。
- 詳細には「YouTube で動画を探す」ボタンを置き、押すと YouTube で `デュエマ {カード名}` を検索した結果のページが新しいタブで開く。
- 画面の下に「非公式のファンサイトです」と、カードの権利表記（公式サイトのフッターに書かれている表記）、問い合わせ先（専用 Gmail アドレス。削除依頼の窓口）を表示する。
- ページのアドレスに絞り込み条件を残し、同じ条件の一覧を人に共有できるようにする（作る人の判断）。

## 6. 作り方の比較

| 案 | 内容 | 長所 | 短所 | 判断 |
|---|---|---|---|---|
| A | 公式のカード検索から自動で読み取る | 公式と同じ正確なデータ。画像の URL も決まった形 | 公式サイトの作りが変わると直す必要がある | **採用** |
| B | DMWiki などのファンサイトから読み取る | 文章の情報が多い | 画像がない。ファンサイトに負担がかかる | 不採用 |
| C | 手で入力する | — | 2万枚以上あり現実的でない | 不採用 |

画像の扱い：**公式の画像 URL をそのまま表示**（採用）。自分で保存する案は、コピーを持つことになり権利面のリスクが上がるため不採用。

YouTube 動画の扱い：

| 案 | 内容 | 判断 |
|---|---|---|
| 見る人がカードを開くたびに API で検索して表示 | 無料の枠（1日約100回）がすぐなくなる | 不採用 |
| 1日1回まとめて動画を集めて表示（チャンネルの新着動画をタイトルで振り分け＋検索） | API キーの準備と毎日の更新処理が必要。関係ない動画が混ざるおそれ | 不採用 |
| **YouTube の検索結果ページを開くリンク** | 仕組みが一番シンプルで、枠もキーも要らない。サイト内でサムネイルは見られない | **採用（ユーザーが決定）** |

## 7. 全体の構成

```
[GitHub Actions]
  ├─ (週1回) カードの読み取り：新しいカードだけ
  └─ (月1回) 全件読み直し
        公式のカード一覧・詳細ページを1秒に1回以下の速さで読む → cards.json
        │
        ▼ 変更があれば GitHub に保存 → Cloudflare Pages に自動で公開
[Cloudflare Pages] 一覧・絞り込み・詳細の画面（ブラウザ内で動く）
        │ 画像                         │ ボタン
        ▼                              ▼
 公式サイトの画像（そのまま表示）    メルカリ・カーナベル・公式・YouTube の検索結果（新しいタブ）
```

サーバー側のプログラム（Cloudflare Workers）や API キーは使わない。見る人のブラウザは、サイトに置かれた cards.json を読むだけ。

### 7.1 カードの読み取り
- カードの ID の一覧を、公式のカード一覧ページ（ページ送り）から集める。その後、詳細ページを1枚ずつ読んで項目を取り出す。
- **週1回**：すでに持っている ID の詳細ページは読み直さず、新しいカードだけ読む。
- **月1回**：全部のカードを読み直し、能力の文章の修正なども反映する（1秒に1回で約7時間。GitHub Actions の1回の実行時間の上限が6時間なので、数回に分けて続きから再開できるようにする）。
- **フォーマット**：「現行」「オリジナル」の2つだけ、絞り込みに使う。公式の一覧ページを各フォーマットで絞り込んで ID を集め、毎回の実行で付け直す（作る人の判断）。
- 出力：`cards.json`。各カードに次の項目を持たせる。
  - `id`, `name`, `reading`（読み。取れれば）, `type`, `civilizations`（配列）, `rarity`, `cost`, `power`, `mana`, `races`（配列）, `abilities`（文章）, `flavor`, `illustrator`, `products`（配列）, `formats`（配列）, `releaseOrder`（発売順に並べるための値）, `twinpact`（2つ目の面がある場合は、その面の項目）
  - 画像の URL は `id` から作れるので持たない。
- 公式の作りが変わって項目が取れなかったときは、黙って空にせず、エラーの一覧を出して止まる。この場合はサイトを更新せず、GitHub からユーザーにメールで失敗を知らせる（GitHub の標準の通知）。

### 7.2 画面（静的サイト）
- `cards.json` を1回読み込み、絞り込みと並べ替えはすべてブラウザ内で行う。24,000枚分で数MB（圧縮後）の見込み。重い場合は、一覧に使う項目と、能力の文章などの詳細を別のファイルに分ける。
- 一覧は、**画面に見えている範囲のカードだけ画像を読み込む**（スクロールに合わせて読み込む）。2万枚分の画像を一度に読み込むことは絶対にしない。
- 「同名カードをまとめる」をオンにしたときは、同じ名前のカードを1枚だけ表示する（初期値はオン。作る人の判断）。
- 絞り込みの項目は、第4章の公式の項目にそろえる（フォーマットは「現行」「オリジナル」のみ）。よく使う項目（フリーワード、文明、コスト、種類、種族、パック）は常に表示し、それ以外は「詳細条件」で開く。

### 7.3 外部リンク
- メルカリ：`https://jp.mercari.com/search?keyword={カード名}&status=on_sale&sort=price&order=asc`（販売中・安い順）
- カーナベル：販売と買取の、カード名での検索結果を開く。正確な URL の形は作る人が確認する。
- 公式の詳細ページ：`https://dm.takaratomy.co.jp/card/detail/?id={id}`
- YouTube：`https://www.youtube.com/results?search_query=デュエマ+{カード名}`（カード名は URL 用に変換する）
- リンクはすべて新しいタブで開く。アフィリエイト用のパラメータは付けない。

## 8. 作る人に任せること
- 画面を作る技術（素の JavaScript か、軽いライブラリを使うか）。
- 読み取りプログラムで使う言語やライブラリ（ただし第4章の速さの制限は守る）。
- 公式のページから項目を取り出す具体的な方法。
- 一覧の細かい見た目（文明の色、文字の大きさなど）。
- ページのアドレス、サイト名。ただし「公式」と誤解されない名前にする。
- ユーザー向けの手順書（GitHub・Cloudflare のアカウント作成から公開までの手順）。

## 9. 公開前に確認すること
- 初回の読み取りで、件数が公式の表示（約24,000枚）とほぼ一致すること。
- PC とスマホの両方で、第3章の「1画面に見える枚数」を満たすこと。
- 画像を読み込めない状態にしても、文字のカードで一覧が使えること。
- 記号や空白を含むカード名でも、メルカリ・カーナベル・YouTube の検索結果が正しく開くこと。
- 公式サイトの作りが変わったとき（読み取りに失敗したとき）、サイトが壊れたデータで更新されないこと。
